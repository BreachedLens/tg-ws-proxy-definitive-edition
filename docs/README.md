# tg-ws-proxy-definitive-edition

Форк [`BreachedLens/tg-ws-proxy-definitive-edition`](https://github.com/BreachedLens/tg-ws-proxy-definitive-edition) расширяет локальный прокси TG WS Proxy, чтобы помогать подключаться к Telegram, когда доступ к его CDN блокируется. По умолчанию используется **Google CDN**: для этого режима не нужны VPN, установка драйверов или права администратора. Работа доменного фронтинга зависит от доступности и правил конкретного CDN и не может гарантироваться для каждой сети.

Прокси работает локально на вашем компьютере. Он не заменяет Telegram MTProto-шифрование и не требует отдельного удалённого прокси-сервера.

## Возможности форка

- **Multi-CDN и Domain Fronting.** Встроенные пресеты: **Google CDN** (по умолчанию), **Fastly**, **Akamai**, **Amazon CloudFront**, **Bunny CDN**, **Gcore**, **Vercel Edge**, классический маршрут **Cloudflare CDN**, а также **Custom SNI / Host**. Доступность и правила маршрутизации зависят от конкретного CDN и сети.
- **Модульная архитектура `bypass/`.** Независимые транспортные реализации с проверкой доступности и переходом к следующему подходящему маршруту при ошибке соединения.
- **Обновлённый интерфейс и трей.** Динамические настройки показывают только поля выбранного режима, а поля Custom — только для Custom SNI / Host. Активный маршрут отображается в окне и подсказке значка трея. Перезапуск прокси выполняется в фоне, не блокируя меню. Автоматическая проверка обновлений при запуске отключена по умолчанию.

## Быстрый старт — Windows

### Готовый EXE

1. Скачайте `tg-ws-proxy-definitive.exe` со страницы релизов проекта.
2. Запустите файл. По умолчанию прокси использует Google CDN и не требует прав администратора.
3. В меню значка в системном трее выберите **Open in Telegram** для автоматической настройки Telegram Desktop или **Copy Link**, чтобы скопировать ссылку прокси.
4. Значок трея позволяет открыть настройки и журнал, перезапустить прокси или завершить работу.

Для ручной настройки Telegram Desktop откройте **Настройки → Продвинутые настройки → Тип соединения → Прокси**, выберите MTProto и укажите адрес `127.0.0.1`, порт `1443` и секрет из окна приложения или журнала.

### Запуск из исходников

Установите Python 3.10 или новее, откройте PowerShell в корне репозитория и выполните:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe windows.py
```

### Сборка Windows EXE

Для локальной сборки установите проектные зависимости и PyInstaller из extra `build`, затем выполните spec:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[build]"
.\.venv\Scripts\python.exe -m PyInstaller packaging/windows.spec --noconfirm
```

Результат: `dist\tg-ws-proxy-definitive.exe` — единый оконный файл без консольного окна.

## Как работает локальный прокси

```text
Telegram Desktop → MTProto proxy (127.0.0.1:1443) → WebSocket/TLS → Telegram DC
```

Приложение принимает MTProto-подключение на локальном адресе, определяет дата-центр Telegram из начального пакета и открывает WebSocket-соединение к соответствующему DC. При недоступности выбранного маршрута используются настроенные fallback-механизмы. Передаваемые данные остаются защищены шифрованием Telegram MTProto.

Если Telegram не подключается, откройте настройки и проверьте адреса DC, выбранный CDN и доступность выбранного маршрута. В некоторых сетях отдельный CDN может блокировать доменное фронтирование или не принимать такой Host; попробуйте другой встроенный CDN.
